# Engagement loops: matrix

Status: PROPOSED (docs only) | 21 Nov 2026 | Owner: `content` | Model: [README.md](README.md) | Words: [COPY-DRAFT.md](COPY-DRAFT.md)

One row per loop. Guardrail codes G1 to G10 are in README section 7. Channel cells: in-app, local push, email. Email is "no" in every row except LP-X1 because email is transactional only at 1.0 (E75). Server push is parked (E79), so no row uses it. Day ids come from `docs/content/lifecycle-playbook/data/events-usa.csv`. "Names on" means the child-name switch is on and App lock is off; "names off" is the default. A day name reaches a lock screen only behind the separate day-name switch (default off, off while App lock is on); every other lock-screen string is neutral.

Playful scope (founder, Option 2, 21 Nov): Fri and Sat notes, one letter-kept line (LP-M2), and in-app wording for the five public days (LP-D1, and in LP-D2 `new_years_day`, `thanksgiving`, `independence_day`, `labor_day`). Every other row is plain. Every playful line stays PROPOSED with a plain fallback; no playful push exists for a library day.

Status words: BUILT (in code today), SPEC (specified, no words or code), SAMPLES (proposed words exist in the catalogue), DRAFT (new words in COPY-DRAFT.md), NONE (by ruling), HELD (needs a later ruling), GATED (needs a named reviewer or counsel first).
