## 3a. Classification row needed before D1

The device holds new things after a yes that the data inventory does not describe. `docs/legal/DATA_CLASSIFICATION.md`, section 4 (device stores, the row "PostHog SDK state (after a yes only)", line 753 at `develop`) says `persistence: 'memory'` and that the queue, ids and flags never touch disk. At `449f667` the adapter sets `persistence: 'file'` (`posthog.ts`), so that row is wrong for any build that enables analytics. It is mine to fix, but this PR is docs under `docs/analytics` only and none of the stack touches `docs/legal/**`, so the change goes in the first PR that makes `file` live, B1 (and must be merged before D1). Proposed replacement:

| Store | Level | Handling |
|---|---|---|
| PostHog SDK files on the phone (after a yes only; created when the SDK is built, which happens only after a yes) | L2 | On file (`persistence: 'file'`): the random analytics id, the queue of events already passed the allowlist, and SDK flags. Not an account id, not a hardware id. Emptied and the id reset on withdrawal (`optOut()`, `reset()`, queue cleared); a later yes starts a new id. Never read by app code, never in logs or a backup export |
| `scribe.analytics.id`, `scribe.analytics.retired_ids` (existing row, line 729) | L2 | Unchanged: the same random id is the one handed to the SDK at construction; retired ids stay only for deletion |

The privacy policy and in-app disclosure must say the id and queue live on the phone (section 4, founder item 4); `legal` owns that wording.
