## Findings, most serious first
- N1 (fact, design choice). 8.2 says "No native SegmentedControl exists." The installed @expo/ui 57.0.21 ships `@expo/ui/community/segmented-control` (iOS: SwiftUI `Picker` with `pickerStyle('segmented')`, `src/community/segmented-control/SegmentedControl.ios.tsx`), and COMPONENTS 2.9 on develop specs exactly that route. None is built in `components/platform/` (true). `ChoiceGroup` is still the right choice: a native segmented control keeps one row and truncates labels at AX sizes, which our never-truncate rule forbids, while `ChoiceGroup` stacks (`:61`). Say that in 8.2 and in the 33-1 rewrite of COMPONENTS 2.9 (why native is not used), rather than that none exists.
- N2 (VoiceOver, the group label). 8.2 relies on a PROPOSED `photos.book.lens.groupA11y`. On iOS the `radiogroup` container is not an accessibility element and RN 0.86.3 sets no `accessibilityContainerType` anywhere (grep of `React`, `ReactCommon`, `Libraries`), so that label is probably never spoken (the file lists it as Unverified). Design for it: each option's label must stand alone ("Months, radio button, checked"), and the group key should be optional, not a blocker for NS-33-R3. The device row should listen for it.
- N3 (VoiceOver, position). RN radios do not say "1 of 2" (no trait, value words only), where a native segmented control would. NS-33-R3 asks for "a single choice among options, with the selected one stated"; "radio button" plus "checked" meets it. Note it so the device walk does not fail it for the missing count.
- N4 (component, progress). 1.2 lifts the `storage.tsx` bar and says "no new library". @expo/ui 57.0.21 has `swift-ui` `ProgressView` and `Gauge`. Our own bar is defensible (tokens, no SwiftUI `Host` sizing, Reduce Motion with no animated fill), but PRINCIPLES 3 wants the reason stated. Also say what VoiceOver reads: `accessibilityValue` with `now`, `min`, `max` (or a text value such as "40 percent"), since `progressbar` alone only adds UpdatesFrequently.
- N5 (undo clock, E1). Agreed with CR-67 AX-11. One gap: 1.1 says `commit` runs at "a screen change". The toast store is shared by the root and tabs hosts (`toast.logic.ts`), so say which navigation event counts (the host unmount, or any route change), and test that `commit` runs once on that event, so a picture's replaced file is not deleted while Undo is still visible on the other host.
- N6 (fact, stale). 8.2 says #840 has "0 reviews at `cc94d0d3`". #840's head is now `f811c9a6` (REST, 11:13 UTC). The tablist fact still holds there; recheck reviews before folding the ChoiceGroup into #840.
- N7 (Bold Text, fonts). 3.2 R14 adds Mukta Bold and Literata SemiBold. Say the CSS map in `dist/` regenerates (33-4 does) and that `faceForClassName` tests cover each step up, including italic (Literata Italic has no heavier face bundled; under Bold Text it must stay Italic, not fall to a synthesised weight).
