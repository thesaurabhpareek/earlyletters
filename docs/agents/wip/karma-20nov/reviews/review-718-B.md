### Findings: no must-fix
1. VoiceOver order. The title is the native header (`Stack.Screen`, outside the ScrollView), so the line cannot be read before the page title in reading order. Inside the page it is now the first element, then the heading "What is erased" (still `role=heading`, so the rotor is unaffected). Not announced twice by the code: `ErrorLine` calls `announce()` once per mount (`auth/ui.tsx:145`), which is a no-op on Android (`a11y.ts:55`), and `accessibilityLiveRegion` is the Android path only, so each platform speaks it once. The announce timing is the same as before the PR.
2. Note, not verified (no device, and the line cannot be shown on a phone): the line is now also the first focusable element. After the Erasing screen swaps for the new ScrollView nothing moves VoiceOver focus (no `useFocusOnMount` here). If iOS lands focus on the first element, the same sentence could be heard twice on iOS (the announcement, then the focus read). Before the PR the first element was the heading, so this could not happen. Low frequency, and not a regression in the other direction (the line is no longer buried). If someone wants it closed, the fix is a focus-on-mount for the line, not a revert. I would not hold the build for it.
3. Dynamic Type AX5. Nothing is lost: the Text has no `numberOfLines`, the page scrolls, the total page length is unchanged (only the line moved), and the Erase button is still last, so the same scroll reaches it as before. The trade is that the line no longer sits next to the button at large sizes. Acceptable, and the right order for a warning. It cannot be checked on a phone tonight.
