### Notes
1. The merge adds behaviour (note above) that the PR body, and the two PASS reviews at 252eadda, do not cover. This is a T2 PR: the Privacy Officer's view and two counted reviews need to be current on this head.
2. `erase-everything.ts:93-94`, `store.ts:1030-1045`: if a recording will not delete, an interactive erase returns incomplete with the rows still there and the pending mark set; the page says "Erasing did not finish. Try again." If the person carries on and writes new letters, the next launch (`resumeEraseAtLaunch`, `erase-everything.ts:120-134`) finishes the erase and removes those too, with no warning. The same would follow if `forgetReminders` never returned. It needs a file the app cannot delete, so rare; earlier reviews accepted a related nit. Cheap mitigation: say on the failed line that it finishes when the app next opens.
3. `Caches/Print/<uuid>.pdf` holds the whole book while an export renders (`node_modules/expo-print/ios/ExpoPrintToFile.swift:100`). `export/device.ts:255-266` deletes it in `finally`, but a kill mid-render leaves it, and neither `cleanupExports` nor `CACHE_COPIES` (`erase-everything.ts:46`) removes it. Add `'Print'` there.
4. `forgetReminders` removes `el.` reminders only. Plan reminders (`plan.` prefix, `billing/plan-reminders.ts:44,77`) stay on purpose (the subscription belongs to the Apple account; their payload carries nothing about a child). S1-133 (f) says "no reminder from the app", which is false for a Plus subscriber. No effect in the alpha build.
5. `resumeEraseAtLaunch` runs in first render and `eraseEverythingLocal`'s transaction (`store.ts:1046`) is not wrapped: a busy or full-disk error at launch reaches the error boundary. Not data loss (the mark stays).
6. `erase-all.test.ts` mocks the whole app-lock controller, so the real reload is covered by develop's `app-lock-behaviour.test.ts` (passes here) and the wiring regex test (cannot run here).
