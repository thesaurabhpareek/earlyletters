### Must-fix 1: the red CI check is a defect in this PR's own new test (not infrastructure, not old copy, not the product)
CI job "web e2e (Chromium)" (job 128689847184) fails one test: `e2e/pages.e2e.ts:81`, "/terms links to the 0.9.0 Privacy Policy, and the link lands". Error: `page error: Transition was aborted because of invalid state. ViewTransition opt-in disabled`, raised at e2e/support/fixtures.ts:153 (the strict fixture fails on any page error). 272 other tests pass. It reproduced on my machine, so it is not a runner fault.
Cause: the old test clicked a `next/link` (client navigation). The PR now renders the text from markdown, so the link is a plain `<a href="/legal/privacy/0.9.0">` inside dangerouslySetInnerHTML (LegalPage.tsx:13). The click is a full page load, which meets the site-wide `@view-transition { navigation: auto }` (src/app/globals.css:150-153). The fixture routes every request through `context.route('**/*')` (fixtures.ts:130, the `problems` fixture), and with that interception Chromium aborts the transition and reports it as an uncaught page error.
Evidence, same built site, headless Chromium, 16 runs each: with the fixture's interception and no reduced motion, 7 of 16 produced the error; with reducedMotion 'reduce', 0 of 16. Without interception, 0 errors in about 20 click-throughs. Real visitors have no interception; I saw no visible fault. Re-running the real test via the repo's config: unchanged test 6 failed of 16; with the fix below 16 of 16 passed.
Exact fix (e2e/pages.e2e.ts, inside that test, before `page.goto('/terms')`):
`await page.emulateMedia({ reducedMotion: 'reduce' });` plus a one line comment saying why (the link is now a full page load; reduced motion turns the cross-document transition off, globals.css:150-153). No source change needed. Note the Web e2e workflow is path filtered and is not part of the `required` job (ci.yml:137), which is green, so the PR could be merged red; do not. This test would then fail about 40 percent of runs for every later apps/web PR.
