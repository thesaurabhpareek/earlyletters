# Agent brief: founder decisions and coordination rules (Oct 3 2026)

Every agent working on this repo reads this file first, then CLAUDE.md, then the docs named in its own task.

## Founder decisions (Oct 3 2026, all Decided)

1. **Standard over custom.** Use what Apple and well-known, stress-tested open-source libraries provide out of the box. Do not build components, payment systems or infrastructure we would have to maintain when a solid standard exists. Add our finishing touches on top.
2. **Quality bar.** Premium and calm, benchmarked against Airbnb, Calm, Headspace, Day One and Apple's own apps. Copying proven patterns from top products is encouraged. Motion and components come from high-quality libraries (Reanimated, Gesture Handler, @gorhom/bottom-sheet, Apple-native views through Expo where they fit), not hand-rolled.
3. **Payments: Apple only, out of the box.** StoreKit 2 with Apple's own subscription UI (SubscriptionStoreView or the closest Apple-provided equivalent reachable from Expo), Apple's restore and manage-subscription sheets, and the on-device entitlement check (Transaction.currentEntitlements). No server of ours sees purchases. No RevenueCat, no App Store Server Notifications endpoint. A co-parent gets Plus through Apple Family Sharing, which is enabled on the subscription. The server-side entitlement tables added on Oct 3 are to be removed, and server code does not enforce Plus. Prices: $3.99/month with a 1-month free trial, $29.99/year with a 2-month free trial. *Note, 4 Oct 2026 (D-080, D-081): prices and trials here are unchanged, but Plus is now the membership that unlocks new letters after 2 free per account. Unresolved conflict, not decided here: this item says no App Store Server Notifications endpoint and no server enforcement, while ADR 0013 and D-001 specify notifications and server checks, and D-080 asks for server enforcement of the letter limit and D-081 relies on `OFFER_REDEEMED`. The founder or lead PM must say which stands.*
4. **Sign-in: simple.** Sign in with Apple, Sign in with Google, and email magic link. Passkeys can be added after sign-in. There are no passwords, so there is no forgot-password flow.
5. **Family at launch: co-parent only.** Other family members and the web contribution page come later. The database already supports contributors; the app hides that path in v1.0.
6. **Languages in v1.0.** Spoken-letter languages are English, Hindi, Spanish, Mandarin Chinese, French, Arabic and Portuguese. Each needs:
   - strong, language-specific transcription (the best open model per language, with fine-tuned open models where they are clearly better and their licence allows it);
   - correct spelling, script and punctuation for that language (Hindi in Devanagari, Arabic right to left, Chinese as characters, accents in Spanish, French and Portuguese);
   - phonetics for taught names.

   The app interface stays in English for v1.0, but must be ready for localisation. Hindi-English code-switching mode is v1.1.
7. **What the machine may do to words (unchanged constitution).** It fixes spelling, script, punctuation, removes "um" and stumbles, and makes tiny agreement slips. It never rewords. Typed text keeps the keyboard's own autocorrect for the chosen language; we never rewrite typed text.
8. **Audio quality.** The original recording is never altered. Use Apple's built-in voice processing at recording time where it helps, and/or proven open-source noise suppression (for example RNNoise, BSD; DeepFilterNet, MIT/Apache) to make a cleaner listening copy. The person can always hear the original.
9. **Deferred to v1.1:** Hindi-English mode, the safety classifier (a static "If you are struggling" row ships instead), word highlighting in Read together, family members hearing each other's recordings (no audio upload in v1.0), Google Play / Android, and the web contribution page.
10. **Beta.** It runs on TestFlight. The store listing never says "beta". The app keeps a small "early version, can make mistakes" note.
11. **Privacy and trust are paramount, and conveyed subtly.** Parents must never doubt that their letters are private, never sold, never used for ads and never used to train models. Say it calmly, in the right places, and back it with real controls. Never be fearful or over-explain.
12. **Analytics.** Opt-in PostHog plus server aggregates, feeding a self-learning loop: agents regularly read the data, write findings and propose backlog items.
13. **Domains.** earlyletters.com is primary and earlyletters.app redirects to it (both at Porkbun). Email runs through Resend: hello@earlyletters.com is live. Legal pages are https://earlyletters.com/terms, /privacy, /health-privacy and /subprocessors. Universal links use https://earlyletters.com. The one-page website is being built in a separate thread on Vercel.
14. **Publisher.** The founder publishes as an individual Apple Developer account.
15. **Lean app, everything else on demand.** The App Store download stays small: the budget is under 40 MB download size, measured on every release build.
    - **Ships in the app:** the code, the English text-rules pack and fonts subset to the glyphs we use.
    - **Downloaded only when needed:** speech models, and language packs for every language except English, fetched only when an author picks that language. Selecting Portuguese downloads the Portuguese pack and nothing else.
    - **Packs are data, not code.** A pack holds rules, filler and negation tables, punctuation profile, phonetic tables and prompt text. It is versioned JSON plus the model file, checked by SHA-256 against a signed manifest. A generic engine already in the app interprets it. This keeps us inside App Store guideline 2.5.2, which forbids downloading executable code.
    - **Hosting:** prefer Apple's own hosting where it fits. Apple-hosted Background Assets / asset packs: verify availability and Expo feasibility. Otherwise use a CDN with free or very cheap egress, for example Cloudflare R2 or Hugging Face for public model files.
    - Packs can be deleted in Settings to free space.
16. **Server-driven content inside native screens (Recommended; the founder may override).** Screens and navigation are native React Native code, for quality, accessibility, offline capture and App Review 2.3.1, which forbids hidden features.
    - **Server-delivered:** prompts, tips, onboarding story cards, announcements, remote config, feature flags and kill switches, and pack manifests.
    - **Format:** typed, schema-validated content blocks (a small block vocabulary rendered by our own components), versioned, signed or hashed, cached on device, and served from an edge cache.
    - **Offline:** the app always works from its last good copy.
    - **Never server-driven:** anything that changes data collection or the paywall, or that could slip past App Review.
17. **API and service quality.** Every endpoint has a latency budget (p95) and an auth check, is safe under retries (idempotency keys) and is rate-limited.
    - Responses are content-free in logs, and requests carry request ids. Requests are signed with user JWTs only; no service keys ever ship in the app.
    - **Public read-only config and manifests:** served from a CDN or edge with long cache plus ETag.
    - **User data:** goes through Supabase RLS and RPCs in one region near US users.
    - **Contracts:** typed and versioned in one shared package (`packages/api`), so client and server can't drift.

## Coordination rules for parallel agents

- **Stay in your own files.** Edit only the files and folders your task says you own. To change something outside them, write the request in your final report instead.
- **Never commit or push.** The coordinator commits.
- **Strings.** New user-facing strings go in a `copy.ts` inside your own feature folder. The content agent moves them into `packages/content` later. Content rules apply everywhere: no em or en dashes, curly quotes, ellipsis characters or emoji; no fear, guilt or loss language; never imply AI writes anything; never gender the child.
- **Installing packages.** Serialise every install, because several agents install at once. From `apps/mobile`, run `flock /tmp/scribe-npm.lock npx expo install <pkg>`; for other workspaces, run `flock /tmp/scribe-npm.lock npm install <pkg> -w <workspace>`. Re-read `package.json` before editing it by hand.
- **Libraries.** Only permissive licences (MIT, Apache-2.0, BSD, ISC) go into the app bundle. Check maintenance status: a release in the last 12 months and an active issue tracker. Verify APIs against the installed version's source or current docs, never from memory.
- **Migrations.** Only new files, with a timestamp inside your own range (given in your task). Never edit an applied migration (see `.github/migrations-applied.txt`).
- **Boot wiring.** Do not edit `apps/mobile/src/app/_layout.tsx` unless your task owns it. Export a `start<Feature>()` or provider and report it; the coordinator wires it in.
- **Before you report,** run `npm test` and `cd apps/mobile && npx tsc --noEmit`, plus `npm run test:db` if you touched `supabase`. Report:
  - your files;
  - test results;
  - what needs a real device;
  - what the founder must do;
  - anything you could not finish.
- **Facts versus guesses.** Mark what you verified versus what you assumed. Never invent library APIs, prices or legal facts.
