# Security risk register

Status: **DRAFT for the exec team's CISO read. Not approved. No risk here is accepted.** Written 27 Nov 2026 for BL-241 (LEGAL-REQ-028). Companion: [WISP.md](WISP.md). Nothing here was run against a hosted project, a vendor console or a phone.

Where the detail lives: D-122 item 3 in [DECISIONS.md](../DECISIONS.md) sends new design-level write-ups, threat-model detail among them, to a second private repository, and keeps requirement rows and shipped code in the public one. The CISO read should decide, under that item, whether the threat-model detail in R-21 to R-23 moves to the private repository and leaves a pointer here. R-24 is written at register level for the same reason.

Every risk comes from a file in this repository, named in its row. Where a fact may have changed since that file was written, the row says the file's date. The scores are the drafter's, for the CISO read to change.

How to read a row:
- **Likelihood (L)** and **Impact (I)**, 1 (low) to 5 (high). Score = L x I. Impact 5 means L4 content (letters, recordings, the child's details) reaches someone it should not, or a credential that opens them leaks.
- **Likelihood anchors** (proposed, for the CISO read to change), each over the 12 months to the next annual review:
  - 1: not expected in 12 months; it needs a precondition that does not exist today, or several controls failing at once.
  - 2: could happen in 12 months; a path exists, but it needs a deliberate actor or one specific mistake, and none has been seen.
  - 3: plausible in 12 months; the path is live and rests on one control that is procedure or has not been read back.
  - 4: expected in 12 months; the gap is open now and ordinary work will meet it.
  - 5: happening now, or expected within the quarter.
- **Controls** say whether each is a test, a setting, or procedure (see WISP section 3). Procedure is not counted as a control.
- **Owner** is a role. **Next** is the next action and its backlog id or founder queue row, if one exists. "No BL id found" means none was found in `docs/BACKLOG.md` for this draft.
- **Review by**: 2027-02-27 for every row, proposed. That is quarterly, the cadence [SECURITY.md](SECURITY.md) section 2.6 sets for the other reviews. The CISO read sets the real dates.
- Accepting a residual risk is an exec-review decision (CR-176; `.claude/skills/early-letters-ciso/SKILL.md` section 4). Until one is recorded, every row is open.

### R-25 Sign-in mail can be read in the sending account
- **What:** sign-in mail carries the links and codes that open a family's account, and so its letters. Anyone who can read that log can read those links while they are valid. Three holders of that read appear in the repo, and a fourth may:
  - The Resend connector attached to agent sessions. It lists and reads sent emails and creates API keys ([SECRETS_REVIEW.md](../security/SECRETS_REVIEW.md) SR-12 and section 7, "High for Resend if it is the product's sending account"). Which Resend account it reaches is not recorded. A session on 27 Nov 2026 still listed those tools (observed, not a repo record).
  - The website's `RESEND_API_KEY` (R-24). The site's code creates, reads and updates contacts with it (`apps/web/src/lib/notify/provider.ts`, and `unsubscribe.ts` through `unsubscribe-handler.ts`), which the sending-only keys in [SECURITY.md](SECURITY.md) sections 1 and 3 cannot do, so it holds a wider permission. Whether that permission also reads sent mail, and whether the key sits in the same Resend account as the sign-in sender, are not recorded.
  - The Resend console, whose reach [ACCESS.md](ACCESS.md) lists as delivery logs (R-02).
  - Possibly the Vercel connector (R-24): it may read the website's `RESEND_API_KEY` directly if the variable is not marked Sensitive (inferred), and a deploy it starts runs with the key either way (inferred); R-24 gives the sources.
- **Source:** SR-12 and section 7 of SECRETS_REVIEW.md; AUTH_SETUP.md section 4; the website code above; ACCESS.md; `.claude/skills/early-letters-ciso/SKILL.md` section 9a. R-16 is the same exposure on Supabase's side.
