## 2. The rule for a split row

- One PR, size S or M, a reviewer reads it in ten minutes (CODE-R02: at most 400 lines and 20 files).
- At most 6 P0 ids per row where the ids are NS card rows, at most 8 where they are function-file rows (those are mostly one test each). Ids that share a screen, a table or a test file stay together.
- Same Mode, Owner and Depends on as the group row; Scope and Done-when follow the group row's wording ("tests first, then code or words only where a test fails"). Satisfies lists the ids exactly, no range that would hold an id the row does not carry.
- When every id of a group has a split row, product sets the group row `superseded (by BL-first to BL-last)`, in the batch that closes it. Until then the group row stays and is not built from.
