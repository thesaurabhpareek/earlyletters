## 2. Cross-card notes

- Claims in notification copy: the cards' bans (greeting, "your", what a day means, count, comparison, "personalised", "smart reminders") are good. The two additions are C-11 (no age norm) and C-01 (no feature advertising). Nothing in the five cards promises "private", "secure" or "never" about the lock screen, which is right, because the name can show behind a switch.
- Children's data: none of the five cards takes data from a child or attaches a tradition to a child or book (NS-47-R3, R5). The child's name never sits in a title (NS-48-R11). I did not re-read COPPA or GDPR Article 8 this session, and no card change is proposed from them.
- Push marketing law: the cards send local notes only; there is no push token (NS-49-R20 is Apple's notification, not ours). I did not read ePrivacy, TCPA or CAN-SPAM. UNVERIFIED whether any applies to local notes; Apple's contractual limits (V2) are the binding constraint I could read.
- Age rating: K6 re-reads the age rating at NS-05 Level 1. Library content about religious festivals is a new input; I did not find a religion question in the visible part of Apple's questionnaire page (UNVERIFIED for the unread 40k characters). Proposed: add NS-46 and NS-49 to the K6 re-read list at the G5 label check.

## 3. Good enough, leave alone

- Nothing ticked for the parent, "Not now" as a full answer, and "Not now" with equal weight (NS-46-R2, NS-47-R25): fits 5.1.1(iv) (V1).
- Everything on the phone, the store L4, one reader, no network request carrying a day, log canary with synthetic keys (NS-47-R1, R4, R8, R11): this is what keeps data "not collected" under V10.
- Neutral title and body by default; day name behind its own switch, forced off under App lock (NS-47-R12, R13): sound once C-02, C-04 and C-06 are in.
- Sign-out clear, Erase scan, Delete account line, nothing in Save a copy (NS-47-R15 to R17, R10).
- No ask in first run and a field-inventory test (NS-47-R18, R19); no "Eastern" option, no prefill from locale (CB-6, NS-47-R20).
- A day note opens a generic prompt and the synced row equals a control (NS-47-R5, CB-3): this is what stops derived religion data leaving the device (V10, last sentence).
- Quiet-tone days, no greeting, no "your", no look-back (NS-46-R16, R17, R22): meets the voice rules and the hard-day risk.
- Computed rule dates, source licence on record, tradition-member review, annual review (NS-46-R12, R23, R24): the right controls for a data licence risk.
- Ticks work with notifications not allowed, and nothing requires the permission (NS-46 l.134): consistent with 5.1.2(i), "may not require users to enable system functionalities (such as push notifications)" (V1) and 4.5.4 "must not be required".
- Volume cannot rise: the catalogue chooses words only, `active` never time-sensitive (NS-48-R2, R16, R24): helps against DPLA 2.3 "unduly burden ... with excessive ... Local Notifications" (V2).
- Level 2 only through Apple's picker with no photo-library permission, no PhotoKit call, level 3 closed (NS-49-R6, R25, R26): matches 5.1.1(iii) "use the out-of-process picker" (V1).
- Only photo and Live Photo content read, file validated, flag-gated entitlement with a `security` read (NS-49-R10, R15, R19).
- One slip, no strip, no count, today only, no list (NS-50-R2, R11): no compliance issue; it also limits what a screen reveals.

Default: no change to the BRAND.md ban; the store name "Baby Journal", the listing sentence about the recent-days picker and Apple's own sheet carry it; counsel confirms (C-14).
3. Hide the country list until a second country ships? Default: yes (C-05); the first release asks about a tradition only.
4. Should a tradition day typed through "Another tradition" follow the same day-name switch as library days? Default: yes (C-04), which needs Karma to rule an NS-18-R3 errata row.
5. Is Christmas Day offered as a public (lock-screen titled) day? Default: no; it sits in the Christian tradition rows with a neutral title (C-02).
