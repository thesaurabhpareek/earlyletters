# Threat model: the product and the tooling that builds it

Status: first version, Wed 28 Oct 2026. Retro package R3-09 (IMP-75, root cause RC5). Required by SEC-R01 (`docs/engineering/06-security-engineering.md:29`), which names this file and says it did not exist. Owner: S01 (`docs/security/**`); any session may update a row with evidence.

**Verdict.** The product's server controls are tested in CI and reviewed (R-17 checklist), but the R-17 gate has not passed. The largest live exposure is the tooling, not the app: scheduled Claude tasks hold write connectors to production systems and are held back only by prompt text (T4), agents post as the founder's GitHub account so trust checks cannot tell them apart (T2, T3), and the coordinator may merge database and CI changes with no human step and no branch protection on `develop` (T9). Five founder actions close most of the tooling risk; they are listed in section 4.

## 0. How to read this

- One row per attack surface. Section 2 is the product, section 3 is the tooling. Each row: assets at risk, threat, current control with evidence, gap, proposed mitigation with owner (founder or agent), and the IMP or RB id that covers it (from the 28 Oct retro synthesis and `infra/robustness-backlog-2026-10-28.md`).
- This file builds on, and does not repeat, three existing documents. Where they go deeper, the row points at them:
  - `docs/security/SECRETS_REVIEW.md` (16 Oct, revised 23 Oct): every secret, environment and connector, with findings SR-1 to SR-15.
  - `docs/ops/SECURITY.md` (3 Oct): function secrets, rotation, least privilege, Supabase settings.
  - `docs/reviews/2026-10-04-security-privacy.md` (3 Oct): findings H1 to H3, M1 to M5 on the 4 Oct wave; and `docs/security/REVIEW_R17_CHECKLIST.md` with `REVIEW_R17_AUTH.md` for the R-17 gate.
- Evidence labels: **[R]** read from the repository at `origin/develop` 6bfb94a9 or `origin/main`, or from the GitHub REST API on 28 Oct 2026; **[U]** unverified, with what would confirm it. Section 5 lists every [U] control in one place.
- No exploit steps. Each threat is stated only as far as needed to judge the risk.
- Data levels follow `docs/legal/DATA_CLASSIFICATION.md`: L4 is a family's letters, raw transcripts, audio and the child's name and dates.
