## 7. Risks

- No run. Every status is from reading; the worktree has no `node_modules`. A green `npm test` is not yet evidence.
- `posthog.test.ts:89` returns early when the SDK is absent, and `analytics-off-v1.test.ts:82` asserts the SDK is not a dependency. In a clean checkout the version pin check never runs. A mutant that bumps the SDK would stay green.
- `allowlist-pins.test.ts` stems are substrings (`place`, `region`, `origin`): they already needed three exemptions, one for `original`. A new honest enum value will trip them; a careless exemption becomes a blanket pass. The "exemption must exist" test keeps the count at exactly 3.
- The `variant_id` test accepts a max of 99 to 399, so it stays green before and after the card's 0 to 399 change. It cannot prove the change happened.
- Titles with no id (BUILT-NOID) are invisible to trace and to the gate. A rename can delete the only guard without anyone noticing.
- Canary tests catch only the strings they plant. A hash, a count or a new enum value carrying meaning passes every canary. Stem lists and the closed enums are the real guard; keep both.
- Flaky clocks: `lifecycle.ts` (30 minutes away, session buckets) and the 60 s flush need an injected clock and `timers`; any test using wall time will flake.
- Insights k = 10 is proven on seeded synthetic data. It says nothing about a real small family (FR-DAT-08, groups under 5 in the repo); the founder reads that by hand.
- Stand-ins: `recordingProvider()` and a fake fetch are stand-ins for PostHog; mark them `[stand-in]` in titles so trace counts them PARTIAL.
