## 0. The frame in twelve lines

1. The pack adds no tier and no service (eval C s0 item 1, adopted). Six cards may touch the server contract (NS-06 A and B, NS-09-R14 as built, NS-12, NS-16 only if a held key is chosen, NS-17 only if S3 is ruled) plus BL-870 (S1). Everything else is `apps/mobile/src`, `packages/content`, and for NS-24 and NS-06 B, `packages/core`.
2. Every server change is additive and server-first, and nothing can retire an old build today: `p_api_version` and `SCVER` are planned, not built (Fact: `packages/api/src/server/sync.ts:23, 45-51`; ADR 0025 section 8), and the app never reads `minSupportedVersion` (Fact: `packages/api/src/remote-config.ts:99`; no match in `apps/mobile/src`).
3. A field group sent to a server that lacks it loses the whole op: `22023 unknown field group` (Fact: `supabase/migrations/20261016000000_sync_v1_server.sql:1031-1032`), classified reject (Fact: `packages/api/src/envelope.ts:225`), and the outbox merges the groups of one letter into one op (Fact: `apps/mobile/src/lib/sync/outbox.ts:278-280`), so a words edit queued beside a Firsts mark goes to `rejected_writes`. Eval A s2.1 found the same and sets a preflight ordering rule; this file adopts it and adds a runtime guard (2.2).
4. The sync contract has two hand-written definitions, `packages/api/src/server/sync.ts` and `apps/mobile/src/lib/sync/types.ts` (Fact: `types.ts:9-12` calls itself the only definition until it moves), and no test ties them (`packages/api/test/contract-drift.test.ts` compares the package with the SQL only). That breaks API-R01 and CODE-R13 for every new group.
5. Old builds tolerate new pull keys because the phone casts the pull (Fact: `apps/mobile/src/lib/sync/engine.ts:241`) and the merge writes named columns only (Fact: `lib/sync/merge.ts:487-499`); they also drop the meaning of a key. An author's second phone on a pre-seal build shows a sealed letter open, and its restore-epoch reupload would publish it (AR-2; eval A R7).
6. Flags: adopt eval C s2.2 (one registry, local flags independent of the server switch, a kill switch only where policy allows) and eval C s2.3 (the G6 preflight), with two corrections (AX-4, AX-7).
7. Numbers are taken at merge, never in a design: local migrations after L11 (`entry_media`, #835), export minors after E1 = 1.7.0 (eval C ADR 0038), server files after the newest on `develop` and in open PRs (`data-and-sync.md` section 1).
8. Four shared structures land before the cards that fill them: the letter-page row model (NS-21), the Home slip registry (`[FRAME-SLIP]`, eval C ADR 0033), the one opening rule for seals (AP-11), and the notification budget (NS-32, eval C ADR 0032).
9. Writing Tools cannot be switched off from React Native 0.86.3 (Fact: no `writingToolsBehavior` in the installed `node_modules`, grep of 20 Nov). Three designs answer it three ways (AX-1).
10. Observability stays content-free by construction: closed error codes per module (eval C s4.2, adopted), keyed to the UX state vocabulary (`<screen>.error-<code>`, `.paused-<switch>`, E-DESIGN state suffixes) and to the J-N18 canary.
11. ADR numbering: eval C s1.4 holds 0029 to 0039 and this file takes no new number. Its contract rules (2.1, 2.2, AP-3) are an amendment to ADR 0025 (sync protocol). I drop eval C's 0034 (seal publication): `data-and-sync.md:111` records the B10.1 choice as an amendment of ADR 0028, which already owns D3 under CR-62, and two records of one mechanism would drift; AR-2's server rule joins that amendment. 0034 stays unused.
12. Staging and production have never been migrated by CI (`data-and-sync.md` section 6, F4). Until that is fixed, every server-first rule above has no server to be first on.

## 2. API and sync contract changes

### 2.1 Rules (chapter 02, applied to this pack)

- **Additive only (API-R11).** New optional keys, groups, op types, codes in an existing class. No rename or meaning change; the one meaning change in the pack is AX-4's `photos` pause.
- **Server first.** A group, op type or prefs key reaches a server before any phone sends it. Op types and prefs keys hold today by compile-time `planned` lists and `sendable*()` (Fact: `sync.ts:191, 201, 959-963`); held ops by what the server's pull shows (2.2). Field groups have neither; 2.2 adds it.
- **Key-present guard.** A new column applies only when its group is in `changed` and its key in the data, as `language` does (Fact: `sync_v1_server.sql:1119`), so an older client never clears it.
- **Tolerant pull, explicit merge.** New pull keys are optional in `PulledRowSchema`; the phone ignores what its merge does not name (section 0 item 5). A key that changes what may be shown (the seal) is not safe to ignore (AR-2).
- **Errors.** A new SQLSTATE enters the chapter 02 registry and `SQLSTATE_RULES` (`envelope.ts:194`) in the same PR, one meaning and one class (API-R09): `SCPHO` (S1), `SCSEL` (S4). The drift test fails on an `SC***` raised in SQL without a rule (`packages/api/test/contract-drift.test.ts:93`). Phone codes are closed unions per module (AP-9).
- **Endpoints.** A new RPC gets an `ENDPOINTS` row with class, auth, retry and rate limit (API-R17), `require_user()` first and NSC-10.
- **Remote config.** A new key is optional with fallback off, so an older signed config parses (`M14_KILL_SWITCH_KEYS`, `kill-switches.ts:39`); an older build drops it; a key only pauses (`kill-switches.ts:1-5`).
- **Export.** Semver; an optional field is its own minor; each v1 minor reads every earlier v1 file (Fact: `apps/mobile/src/lib/export/schema.ts:7-8, 26-28, 90`); minors by merge order (eval C ADR 0038).

### 2.2 Two closures before the first new group (owner `sync`; review `principal-architect`, `data-steward`)

1. **One sync contract.** A drift test in `apps/mobile/test/`: `ALL_GROUPS` equals `FIELD_GROUPS`, the phone `PulledRow` and `EntryData` keys equal `PulledRowSchema` and `ENTRY_DATA_KEYS`, with a mismatch fixture as positive control. Then, in its own PR, the phone imports the constants from `@scribe/api/server` (`lib/billing/status-report.ts` already imports from it).
2. **The server advertises, the phone sends.** Fact: held ops already wait until the server's pull carries a `held` section, because an older server would refuse them (`outbox.ts:772-779`, setting `heldServer`). Rec: generalize it once. `sync_pull` returns `caps` (PROPOSED: the groups, op types and prefs keys this server accepts; AC-16); the phone stores it; the outbox drops from `changed` and `data` any group not advertised, keeps the local value for a later push, and holds an unadvertised op queued. Exception, fail closed: a group that narrows who may read a letter or what the server keeps (`seal`; `words_withheld` if S3 is ever ruled; any later privacy or hidden-from group) is never dropped. The whole op for that letter holds until the server advertises the group, as today's `22023` refusal fails closed (`sync_v1_server.sql:1031-1032`). Today `in_book` is the only narrowing group, and every server since v1 accepts it. `PLANNED_FIELD_GROUPS` joins `PLANNED_PUSH_OP_TYPES` so the drift test accepts a group the SQL lacks. Tests: a words edit queued with an unadvertised widening group (for example `first`) is applied; a sealed letter queued against a server without `seal` in `caps` sends nothing for that letter, and sends it whole, sealed, once `seal` is advertised (NS-06-B8, P0). This complements eval A s2.1's preflight rule (a build's flag stays off until its migration is in `.github/migrations-applied.txt`): the preflight protects store builds, `caps` protects every build against every server, including staging and a production project behind the repo (F4).
