## 1. Ingestion pipeline

**1.1 Two doors, one pipe (NS-52-R2).** Door 1: the system picker, multi-select, images and videos, from "Start from a photo" and Review's Add control. Door 2: the NS-51 moment sheet (parent's own library pictures). Both hand plain-named originals in `Caches/ImagePicker/` to one function, `lib/photos/ingest.ts` `ingestItems(owner, items)`. No camera, no third-party picker (NS-52-R2, R38; `LIBRARY-DECISIONS-A-ui-media.md` LD-07, LD-12).

- **Door 1, native.** `scribe-photo` gains `pickMany(limits)`: `filter = .any(of: [.images, .videos])`, `selectionLimit = remainingPictures + remainingVideos` (one number for all types, so the per-type limit is checked after the pick; `ALREADY-HAVE.md:54`, LD-08), `selection = .ordered` (Unverified: the iOS 15 ordered-selection option; the spike confirms) and `preferredAssetRepresentationMode = .current` as today (`ScribePhotoModule.swift:138`). The surplus beyond a per-type limit is refused with `media_limit` and one calm line; nothing already chosen is lost (NS-52-R1). It keeps the `Progress` it discards today (`:167`) and sends it as the P-1 event (`11-foundations.md` 8.4), now per item. Videos copy inside the `loadFileRepresentation` handler, because the provider's file lives only for that call (Unverified; same as pictures today).
- **Door 2, native.** `scribe-photo-library` (the card's name, `27:199`; handoff 24's `scribe-library` loses by CR-66) copies a chosen asset's original with `PHAssetResourceManager.writeData(for:toFile:options:)` to the same plain-named folder, with network access allowed only after the parent chose the item (NS-51-R21 allows none for the index and thumbnails). Its allowed calls are the NS-51-R29 allow-list; the copy is "attach", which R29 permits.
- **Module split (default: the card's `scribe-photo`; Rec: a sibling; Conflict C-12).** Card 27 section 10 puts the multi-select pick, the bounded video check and the re-encode in `modules/scribe-photo` (`27:410`), and NS-01-R22's "no video" wording is struck, not kept, so that is the default and the video steps below read "in `scribe-photo`". A sibling `scribe-media` would hold probe, encode, strip, poster and hash; cost: the plain-name guard (about 30 lines, `ScribePhotoModule.swift:92-107`) exists twice, held by one shared vector file both scans read, and a second hash pin. Karma rules; the PR table assumes the default.

**1.3 Concurrency with the take (Rec; OQ-M6).** A video encode starts only while `captureBusy()` is false (`capture/busy.ts:20`; `11-foundations.md` 1.4). If the parent taps Speak while it runs, the encode is cancelled, the temporary original stays in `Caches`, and the encode restarts after the take ends; Speak is never made to wait (core loop, NFR C-01). The temporary original goes on Cancel, on kill (next launch sweep), on a lock, and at Keep or Let it go. On background, the session ends with an error; it restarts in the foreground (R33; Unverified: the exact `AVError` code, so the code treats any export failure while not active as "restart", with at most two restarts).

**1.4 Failures (all per item; the rest stay; words intact, NS-52-R11).** Closed code union, no value in a code, no identifier in a log (`OBSERVABILITY-WITHOUT-CONTENT.md:16`): `media_not_available` (iCloud, offline), `no_space`, `video_unreadable`, `video_too_large`, `video_too_long`, `media_limit`, `media_missing` (reading), plus NS-01's picture codes. Each is one calm line from a PROPOSED key (`features.photos.media.noSpace` and the others, `27:462`); no sound, no haptic on a failure (`27:"Never"`).

## 2. Lifecycle

**2.1 Remove one item (NS-52-R15).** Review hides the item in memory and shows the Undo toast built on the one undo clock: `createUndo({ revert, commit })` (`11-foundations.md` 1.1), where `commit` runs once at the toast's dismissal. `commit` is `removeMedia(id)`: delete the derived copies, the poster, then the primary file, assert none exists (throws and keeps the row if one remains, as `erasePictureOf` does, #840 `device.ts:102-109`), delete the row, renumber the owner's positions. A kill inside the window leaves the item in place (nothing lost; the parent removes it again). OQ-M7.

**2.2 Delete, restore, purge, Let it go, erase (NS-52-R16; ADR 0028 D5; NS-36-R1a to R1d).**
- **Delete a letter:** files and rows stay, hidden by the join to `entries.deleted_at` (D1: no `deleted_at` on the row). **Restore:** no media write. Recently deleted media still count in Me, Storage, so the size the parent sees is the size on the phone (Rec; R31).
- **Purge, Erase now, `finishServerErased`, `eraseBook`:** the one eraser, `erasePictureOf(entryId)` (name kept for #835's call sites), loops the owner's rows (already so, #840 `device.ts:102-109`). Per row the file order is: derived copies, poster, primary file; then the row. A kill between two files leaves a row with its primary file and no poster: the reader makes the poster again (regen, NS-37-R3). A kill after the primary file leaves a row with no file: ADR 0028 D5's "row without a file, harmless" case. Never a file with no row that anything can reach. This is the order the mutants in part 3 pin.
- **Let it go on a draft:** already erases. #840 registers the eraser for drafts (`capture/erase.ts:32` `setDraftPictureEraser(erasePictureOf)`, used by `finishDiscard` and `deleteDraft` in `store.ts` near `:1294`), so the earlier note on #835 is stale. NS-52 only has to keep it multi-item (the eraser loops the owner's rows) and prove it with a test over two videos (`[NS-52-R16]`).
- **Erase everything:** delete the whole `photos/` and `media/` folders by listing them (strays go too), `Caches/ScribeMedia`, `Caches/ImagePicker`, the `moments/` folder; then `removeEverything` clears `entry_media` as an ordinary table. `CACHE_COPIES` (`erase-everything.ts:50`) gains the two new cache names; the test enumerates every folder this file names and fails on a missing one (the FR-PRV-34 scan, 0 media bytes). Works with `EXPO_PUBLIC_PHOTOS` and `EXPO_PUBLIC_VIDEO` off (NS-01-R19, NS-52-R42).
- **Sign-out:** keeps the book and its media (D1); clears the moments folder (NS-51-R17).

**2.3 Backup, restore, new phone.** Pictures, videos and posters are in the iPhone backup like pictures today (ADR 0028 D1, `files.ts:3-4`); derived copies are not (NS-37-R4). A restored phone gets the rows with `scribe.db` and the files with the backup. A new phone with no iPhone backup gets the letters' words from the server and no media: the where-it-lives lines say so (NS-52-R19, R36). Honest cost (OQ-M2): a family's videos in the iCloud backup count against the person's iCloud storage (Apple's free tier is small; Unverified here). The default is the card's: they are in the backup, the line says so, Me, Storage shows the size.

**2.4 The launch sweep, extended (`sweepPhotos`, #840 `housekeeping.ts`).**
1. List `photos/` and `media/` once each; match names by shape (`isStoredName` becomes `isStoredMediaName`: `<id>.jpg`, `<id>.mp4`, `<id>.mov`, `<id>-p.jpg` and the derived `-512`, `-1280`, `-p512` forms; a name of another shape is neither removed nor counted, as today).
2. A stray file (no row) is removed, after the age guard below. A derived copy whose row exists is never stray.
3. **Missing file, row kept (Rec; Conflict C-3).** Today a row whose file is missing is deleted (`missingFileRows++`, #840 `housekeeping.ts:53`). NS-52-R40 wants a plain box, one calm line and the words intact, and a restore can bring files back after the first launch. Rec: stop deleting such rows; the reader shows the box; Remove deletes the row. NS-01-R36 (P0) still lists the old behaviour; product decides (Conflict C-3). Until it does, this part changes nothing for pictures.
4. **Race guard (Rec).** The sweep runs after the first frame and is not awaited (`sweep.ts` header); an encode can move a file in before its row is written. The media sweep skips any file younger than 120 s and skips the folder while `mediaIngestBusy()` is true (a module flag like `captureBusy`). Test: a file moved in and a sweep started before the row insert leaves the file.
5. A row whose owner is gone loses its files first, then the row (as today).

## 3. Export and Save a copy (NS-52-R17, R18; NS-11; NS-36-R2, R5, R7)

**Facts.** `pack.ts` streams the ZIP out with fflate `ZipPassThrough`, but holds one whole file in memory (`readFile(uri): Promise<Uint8Array>`, `sha256(data)`) and has no ZIP64: `MAX_EXPORT_BYTES = 3_900_000_000`, over it `ExportTooLargeError` (`pack.ts:14, :21, :94`). The spec promises ZIP64 and a split per child-year above 2 GB (`DELETION_AND_EXPORT_SPEC.md:322`). Today's export folder is `Caches/exports` (`device.ts:78`) and the low-space guard is `estimate x 1.1 + 50 MB` (`device.ts:288`).

**Design.**
- **Schema.** Keep 1.7.0 as designed (`11-foundations.md` 8.3: `photo: null | ExportPhoto`, the card wins). The next free minor at merge (E5) adds `ExportEntry.media: ExportMedia[]` (`kind`, `file`, `bytes`, `sha256`, `width`, `height`, `duration_ms | null`, `position`, `text`, `place`, and for a video `poster: { file, bytes, sha256 }`), `counts.videos`, and keeps `photo` as the first picture (null if none) so a 1.7.0 reader still works; `additionalProperties: false` stays per version. Files: `photos/<entry_id>/<media_id>.jpg` (ADR 0028 D2), `media/<entry_id>/<media_id>.mp4` and `-p.jpg`. Golden: freeze `_v1.7.0/`, add `_v<next>` with one Asha picture, two synthetic videos from `scripts/qa/asha-book/media.mjs` (never real media, NS-52-R39). If BL-933 has not merged when this one is ready, fold both into one minor (OQ-M8).
- **Streaming.** `PackDeps` gains `readChunks(uri, size): AsyncIterable<Uint8Array>` and `sha256File(uri): Promise<string>`. `sha256File` is a native CryptoKit streaming function in `scribe-photo` (the module that already writes and hashes media; the NS-01 hash step lives beside it); `readChunks` is implemented in `lib/export/device.ts` over an `expo-file-system` file handle read in 1 MiB steps (Unverified that SDK 57's `File` exposes a handle; else a native `readRange` in `scribe-photo`). Media entries use them and push each chunk to `ZipPassThrough`; the manifest takes the row's `sha256` and the verify step compares the native hash of the stored file with it. Peak memory stays near one chunk (NFR M-04: under 150 MB). The in-memory path stays for small files.
- **Size.** `estimateExportBytes` counts media and posters; the size line before the start (R17) reads that estimate; low space is refused before writing (`no_space`, never silent). Above 3.9 GB: the split of spec 4.2 by child-year, then by half-year if one year still exceeds it (Rec), is its own PR and must land before `EXPO_PUBLIC_VIDEO` turns on in any profile (OQ-M5; the NFR D-06 fixture of one letter at the limits is 224 MB, so 18 such letters reach the limit [E]). Interim hold, not a workaround: video flag stays off.
- **Share a copy** is the iOS share sheet handed the ZIP (X2: the parent's own act, as recordings today; `11-foundations.md` 8.3). **NS-05 Share picture** keeps at most one picture and never a video: the payload type is `{ picture: PictureRef | null }`, with `kind: 'photo'` a literal, so a widening is a type error (NS-52-R37; test is a `tsd`-style compile test plus a runtime assertion).
- **Metadata.** No segment or atom in any exported media; the export test runs the same box parser over each exported video (NS-52-R5 names the Save a copy file).

## 5. Reading, playback and the switcher (NS-52-R13, R28, R30)

- **Player.** `expo-video` 57.0.5 is adopted, gated (LD-10 `LIBRARY-DECISIONS-A-ui-media.md:69-77`): one wrapper, `components/media/video-poster.tsx`, is its only importer; `file://` URIs only (an adapter and a scan); the plugin options for background playback and Picture in Picture stay off, with a test that `app.config.ts` passes none, because the label guard does not catch `UIBackgroundModes` in a PR (LD-10; the preflight does, `preflight-testflight.mjs:599-600`). One player instance per letter page, created on the first tap. No autoplay, no loop; audio only after the tap; pause on `inactive`, on App lock and on leaving; keep-awake released at once. The silent-switch behaviour of the player's audio session is Unverified: a device row decides, and the wrapper sets the session category explicitly rather than relying on a default.
- **Switcher.** Posters, pictures and the player surface use the same inactive gate as pictures (NS-01-R13a, E18): an opaque box before the snapshot, with or without App lock. AirPlay and Picture in Picture off (R30).
- **Words per item.** The "Describe this" text is `photo_text` (OQ-M3); the field label is a PROPOSED key; Writing Tools are off (D2, ruling AX-1 in `README.md`); VoiceOver reads "Video, 42 seconds" built from `duration_ms`, never a description (R28).

## 6. Find and the Photos lens (NS-52-R41; NS-37; NS-02-R5)

- **Find.** One change: `photoTextSource.textSql` reads `LIMIT 1` (`find/sources.ts:53`), so only one item's words would be indexed. It becomes a `group_concat` of every item's `photo_text` and `place` for the letter, ordered by `position`, and the media edit paths call `reindexLetter` (NS-02-R16a already names "a photo word or place edit"). A test with three items, words on the second and third, finds the letter. Find never reads a file, a duration or a type (R41, NS-02 Not in scope). The index is rebuilt, not migrated (ADR 0028 D4). A test that changes `textSql` inside one process must call `forgetSearchView`, because `ensureSearchView` caches by source ids only, not by the SQL text (so the view is not made again by itself in that process; at the next launch it is).
- **Lens.** `photosLens` returns `Map<entryId, StoredMedia[]>` sorted by `position`; a lens card per letter shows the first item: a picture's 512 copy, or a video's `-p512` with a play glyph and the label "Video, 42 seconds" (OQ-M4: product may want one card per item; the default keeps NS-01-R11's "no total" and the Book's own letter cards). Absent when no item exists (NS-01-R10 to R12). Uses `ChoiceGroup` and `AnimatedSectionList` as `11-foundations.md` 8.2 and 7.
- **NS-37 copies.** Under the existing design the copies are written natively because `expo-file-system` cannot set the backup flag; `ScribeFiles.setExcludedFromBackup` can (part 1 F6), so `makeCopy` is optional rather than forced (Conflict C-6). Either way the sweep and the eraser learn the new names in the same PR (NS-37-R5, P0).
