## 1. NS-50 Home today: the slip registry and `chooseSlip`

### 1.1 What is built
**Fact** Home renders every waiting draft as a `DraftCard`, or one `HeldRow`, or one "A month ago" card, plus the Plus line (`apps/mobile/src/app/(tabs)/index.tsx:52-54, 207-209, 259, 322`) [V]. **Fact** No slip host, no registry, no seal-opened line, no Save a copy slip exists (`git grep -n -i slip` finds only unrelated hits) [V]. **Fact** Our design for NS-23 PR 1 creates the registry `components/tonight/home-slips.ts` with four slips and the `[FRAME-SLIP]` test (`10-reading-and-family.md:131, 136`); neither is built. So NS-50 does not edit a built registry; it changes the registry's planned content (Conflict C-3).

### 1.2 Registry (data) and the pure chooser
`components/tonight/home-slips.ts` (owner `mobile`; the file NS-23 PR 1 creates; `SlipCard` and `SystemLine` are `design-systems`, COMPONENTS R11):
```
export const HOME_SLIPS = ['waiting', 'sealOpened', 'dayToday', 'saveACopy', 'daysAsk', 'pastLetter'] as const;   // NS-50-R5, oracle order
chooseSlip(input: SlipInput, today: IsoDate): SlipId | null    // pure; first due slip in HOME_SLIPS order
```
- Each id has a `due(input)` predicate in its own pure module. A rank whose provider is not built returns "not due", so ranks 2b and 3b can ship before 2 and 3 (`24:42`; NS-50 section 10 "registry accepts absent ranks"). The `[FRAME-SLIP]` test fails on a slip type not in `HOME_SLIPS` and on more than one slip rendered (NS-50-R1, R11). The oracle order in the test is NS-50-R5's six; the test reads the array, so adding a rank is one line and one oracle edit.
- Rank 1 `waiting` keeps its list (NS-50-R11); no screen shows a count of things waiting. At most one slip renders at a time; a dismissed slip's successor shows at the next Home visit, never in the same visit (NS-50-R6; C M-3).
- `dayToday` is due when: the flag is on and not paused; the active book is not quiet or hidden and "Include in my reminders" is on (NS-50-R8, R-IA-6); `daysForDate(today)` is non-empty; `dismissedOn` is not today or later by string compare (file 13 section 5). It never reads a date other than today (NS-50-R2). A birthday the same date yields: `dayToday` is not due when the active book has a birthday today (NS-46-R7; the chooser already dropped the library note, and the slip follows it so the two surfaces agree).
- A typed day keeps its line in the prompt block and is not a slip (`21:1033`, A W9). If a library day and a typed day fall on one date the typed day's line shows and no library slip (`21:1056`).
- `SlipInput.dayToday` is `{ nameKeys: string[], tone, count } | null` from `lib/days`; the registry file imports no content key of a day (NS-47-R11): `lib/days/home.ts` returns resolved display strings for the slip, and only when today. No id, tradition or country crosses.

### 1.3 Reading the store without delaying Home
**Fact** The days table and file are read lazily (file 13 section 3). **Rec** `useDaysToday()` (in `lib/days/home.ts`) starts after first frame, caches in memory, and is invalidated by `subscribeDays`. Until it resolves `dayToday` is null and no slip shows. When it resolves the slip arrives with `m.enter.group` (NS-50-R12, MOTION). **Risk R-1** the slip is inserted above the prompt block after first paint, which can push Speak and Type down once; NS-50-R4 says Speak and Type never move between visits. Mitigation order: (a) `design-systems` decides whether Home's layout reserves the slot height on a day with a ticked day; the days module can tell Home "a day is ticked for today" from the in-memory cache seeded at the previous foreground; (b) failing that, the slip enters before the cluster is interactive (cluster position is already fixed bottom-anchored, `A-S01` per `7e684984 e2e A DESIGN.md:18` [U: layout not opened]). Device row: SE 3, default size and AX5, cold launch on a ticked day, record whether Speak moved (file 16 DV-3). **Only a phone proves this**: no CI test can show Speak moving after first paint, so R-1 stays open until DV-3 is run by `qa` and the founder. No awaited work is added to launch (A-NFR-001).

### 1.4 "Not today" (NS-50-R7)
Own key `days.close.notToday` (PROPOSED), not `en.common.notNowButton`, which stays the Days ask's answer. Tap writes the field `dismissedOn = <local date>` inside the days file (file 13 section 4.2), not a setting: a date beside a public-calendar day name is derived from a ticked day and inherits its class, so it stays out of the backed-up `settings` table; no haptic, no Undo (the slip is not an answer to anything, A-J flow 3b). VoiceOver hint "Hides this until tomorrow" (key `days.close.hint`). A day change removes the slip with no animation.

### 1.5 Quiet day (NS-50-R15, NS-46-R13; CL-029)
A `quiet` day shows the day's name and `days.landing.quiet` ("The book is open if you want it.", intent); the prompt block (prompt and Another thought) is not drawn for that local day, including after "Not today" (A flow lines 135-136, e2e A DESIGN at `7e684984`); Speak, Type, Start from a photo, Not much today are unchanged. No question mark anywhere on the screen's words that day.

### 1.6 Blank snapshot (NS-47-R26, NS-50-R9; E18)
**Fact** `PrivacyCover` draws only under the lock layer (`components/app-lock/privacy-cover.tsx:1-30`; PD2 row NS-50-R9) [V]. **Rec** a small `lib/privacy/blank-on-background.logic.ts` (pure: `shouldBlank({ route, hasDayName })`) plus one effect in the tab layout that raises the existing cover on `AppState` `inactive` while Home shows a day slip or Me shows C-S24 to C-S26, whether or not App lock is on. The cover is `design-systems` property; mobile only mounts it (hand-off line). **Unverified** that iOS takes the switcher snapshot after the JS `inactive` event renders; `NS-01-R13a` and #838 built the same rule for pictures (`18:26` E18), so the proven pattern is reused. Device row DV-5. **Only a phone proves the snapshot** (the unit test proves the cover is raised for the right routes, not that iOS captured it blank).

### 1.7 Motion and accessibility hooks (points at #921 to #923)
The slip uses `m.enter.group` on cold launch, in place on later visits, `m.list.remove` on dismissal, none on a day change; under Reduce Motion each is `m.fade` at most 200 ms or a jump; no haptic (NS-50-R12). The ids and test method come from `MOTION-ACCEPTANCE.md` (#922, `f9ff7c40`; frame and time budgets section 6, `MA-01` Home cold launch, `motion.md:101`), and the VoiceOver, Dynamic Type to AX5 and Voice Control rows from `A11Y-ACCEPTANCE.md` (#922, sections 2 to 6) and `EXPERIENCE-ACCEPTANCE.md` (#921). **Fact** Neither of those files has an NS-46 to NS-50 row (a grep of `a11y.md`, `motion.md`, `delta.md`, `catD.md` finds none [V]); file 16 proposes them. The slip is one non-interactive element labelled "{name}. {line}" with a custom action and a separate visible 44 pt button (a full-width row from AX3), `surfaceRaised`, `radius.md`, 16 pt padding, `callout` in `text` (NS-50-R14); this uses `SlipCard` of COMPONENTS R11 and adds no new component.
