# Reference: how Early Letters works today

As-built reference pages, so that a founder, an engineer or an agent can answer "how does X work, and where is it" without reading the code. Each page describes what is on `develop` now, not what is planned. Plans live in the PRD, roadmap and backlog; reasons live in the [decision register](../decisions/README.md).

Owner: the `reference-docs` agent (`.claude/agents/reference-docs.md`), which updates these pages every day.

## The pages

The index of all documentation, including these pages, is [docs/README.md](../README.md).

## How a page stays true

Every page starts with frontmatter:

```yaml
---
title: Mobile app
owner: reference-docs
covers: [apps/mobile/src/**, apps/mobile/app.config.ts]
verified_at: 56ec5b5
verified_on: 2026-10-15
---
```

- **covers** lists the code the page describes. When any of those files changes after `verified_at`, the page is stale: the owner reads the changes and updates the prose, then moves `verified_at` to the commit it checked.
- **Facts blocks** hold lists that can be read straight from the code (screens, migrations, tables, workflows, build profiles, packages, agents). They sit between `<!-- facts:<name> -->` and `<!-- /facts:<name> -->` and are regenerated by `node scripts/docs/reference.mjs --write`. Never edit inside a facts block by hand. The available blocks are the keys of `RENDERERS` in `scripts/docs/facts.mjs`.
- **Prose** explains what the facts mean: how the pieces fit, the flow of data, what is on the device versus the server, what is built versus parked for a later release, and where to look next. Cite paths, not line numbers, because line numbers go stale first.

`node scripts/docs/reference.mjs --check` reports stale pages (with the files that changed), facts blocks that are out of date, broken frontmatter, and code areas that no page covers.

## Writing rules

- Describe what exists. If something is planned or parked, say so in one line and link the decision or backlog id.
- Short sections, tables for anything with more than three rows, plain English. No em or en dashes, curly quotes or emoji.
- Never restate a decision's reasoning, a requirement, or a rule from the engineering compendium: link it.
- Never include secrets, real family details or user content. Examples use the fictional Asha family.
