Reviewer: independent QA/security pass (read-only). Worktree at `ca02e820` (develop), website read from `origin/main` (`apps/web` is not on develop).
Scope: D-054 (Apple, Google, email link plus code, no passwords); D-121/D-126: build 1 (`production`/`testflight`, `EXPO_PUBLIC_SERVER_FEATURES=off`) has no sign-in at all, the `(auth)` layout redirects home (`apps/mobile/src/app/(auth)/_layout.tsx:23`). Legend: **V** = verified (ran it or read the code path end to end). **I** = inferred (depends on hosted dashboard state or Supabase server behaviour not run here).

## What holds up (V)
- Enumeration: one call, `signInWithOtp({ shouldCreateUser: true })` (`apps/mobile/src/lib/auth/email.ts:35-38`), so new and known addresses get the same response and screen. Only the email body differs (confirm vs sign-in), which only the inbox owner reads.
- The link is bound to the phone that asked: a Keychain pending note (time only) plus PKCE through a manual-redirect GET `/auth/v1/verify` and `exchangeCodeForSession` (`email-link.logic.ts:79-135`, `email.ts:70-97`). Implicit-flow tokens in a redirect are refused (`email-link.logic.ts:176`). A link never replaces a signed-in session (`session-provider.tsx:422`).
- Token hash only in the URL fragment, in templates (`supabase/templates/magic_link.html`, `confirmation.html`) and on the website fallback page, which verifies nothing and strips the fragment (`apps/web/src/app/auth/confirm/AuthConfirm.tsx` on main). The custom scheme never carries a secret (`links.logic.ts:73-77`).
- No `{{ .ConfirmationURL }}`, no `{{ .Data }}`, no images or trackers in the auth templates; every href is `earlyletters.com` or the `{{ .SiteURL }}` callback.
- Code screen: one-time-code AutoFill, paste normalisation, auto-submit once, 60 s resend wait, address shown back to the person with "Use a different email", client pause after 5 wrong codes per address (`errors.logic.ts:296-304`).

## Journeys (build 2)

| Journey | What the person sees | Status |
|---|---|---|
| New user | Enter email, "Send link", "Check your email" with the address shown. Email "Confirm your email to start your book" with link plus code. Link (same phone) or code, then consent (Terms, 18+, sensitive data), then the claim screen. | V (code); email delivery and hosted confirm setting I |
| Returning user | Same screens and same response (enumeration-safe). Email "Your sign-in link and code". Claim screen shows a masked address before letters join. | V |
| Link opened on another device | Phone without a pending request: "This link can't be used here" plus "Type the code from the email on this phone instead" (no request sent). Desktop browser: website page, verifies nothing, says type the code. Phone B with its own pending request: see SIGN-06. | V / SIGN-06 I |
| Expired link | Pending note over 1 h, or Supabase `otp_expired`: "That link has expired. Send a new email for a fresh one." with Send a new email first. Expiry length depends on the hosted setting (SIGN-02). | V (app); 900 s I |
| Wrong code x5 | Each wrong code clears and refocuses: "That code didn't match...". 5th wrong in 15 min: field locked, "You can try a code again in 15 minutes" plus the link still works (BL-475/476 cover its truth). Pause is memory only; restart clears it; server limit is per IP only. | V |
| Typo in email | The address is echoed on the code screen with "Use a different email" (keeps the typed text for editing). Re-sending the same address within 60 s shows the wrong "paused for an hour" line (SIGN-01). A typo creates an unconfirmed user at a stranger's address, harmless without this phone. | V |
| Hide My Email | Apple sign-in uses the relay address as the account email; email sign-in to a relay address works only after Apple relay registration (`supabase/auth-email.md` section 6, founder step, unverified). A relay user who later types a real address gets a second, empty account; the "No book here yet / Try another way" screen and "Last time you used Apple" hint cover it. | I |
| No email arrives | 60 s then "Send a new email"; "Trouble signing in?" shows: check Spam, from `hello@`, use Apple or Google, write to us. No trouble email is sent (SIGN-05). Google is named but not offered (BL-475). | V |
