# Segment D: money, notices and leaving

Validated 4 Oct 2026 on branch `release/ios-v1.0` at 1494d35. Read-only: nothing in the repo was changed.

## 0. Headline findings

1. **No purchase code exists.** There is no `expo-iap`, StoreKit, RevenueCat or notifications package in `apps/mobile/package.json` (deps at lines 19-35 list only expo-audio, expo-sqlite and similar). `apps/mobile/src/lib/` has no `plan.ts`. `hasPlus()` is a stub returning `false` (`apps/mobile/src/lib/store.ts:301-304`). `currentUserId()` returns `null` (`store.ts:297-299`), so there is no sign-in, which means no purchase, restore, sign-out or account deletion either. The Plus button is permanently disabled (`apps/mobile/src/components/child/plus-gate.tsx:43`, copy `plusNotYet` "Plus is not open yet in the beta", `packages/content/src/strings.en.ts:757`).
2. **The D-051 letter limit exists nowhere in code.** Not in `packages/core/src/plan.ts` (no `add_letter` gate, no `free_letters_allowance`), not in the app save path (`store.ts:437` `saveLetterFromDraft`, `store.ts:418` `saveEntry` insert unconditionally), not on the server (no migration touches entries for Plus; no `free_letters`/`letter_limit` anywhere in `supabase/`). Today the app has unlimited free letters. The only gate is on a second child's book.
3. **CONFLICT (code and tests still encode the 3 Oct plan).** The engine and its tests say first book free and writing never gated; D-051 says 2 letters per account free and writing gated after that. Details in D3 below.
4. **Server entitlement layer is built and tested but PENDING.** `supabase/migrations/20261003010000_children_and_entitlements.sql:4` says "PENDING: not yet applied". It has `store_subscriptions`, `store_notifications`, `apply_store_transaction`, `has_plus`, `book_has_plus`, `get_plan_state`, `my_app_account_token`. There is **no** Edge Function directory (`supabase/` holds only APPLY.md, migrations, tests), so nothing receives App Store notifications, verifies JWS, reconciles, or sends notices. There are no `notice_windows`, `notice_schedule`, `plan_cards` tables.
5. **No notice engine, no trial acknowledgement, no renewal reminders, no price-change notice** exist in code. The schedule is a design (D-022 table, TDD 08 4.3) only.
6. **Docs disagree with each other in places** (listed in section 3). Several are real blockers for the build.
