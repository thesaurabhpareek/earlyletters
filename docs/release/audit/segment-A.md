# Segment A: first hearing about Early Letters to a first-run app ready for the first letter

Validated 2026-10-04 by reading code and running tests. Nothing in the repo was changed. Line numbers are from the files as read today.
Note: docs/prd/A-entry-and-auth.md and B-first-run-and-family.md changed on disk while I worked; I used the current text. `git status` shows untracked `.claude/`, `docs/release/`, `scripts/` that I did not create.

## 0. Bottom line

- Website and waitlist (A1-A9) are real, tested and close to launch-ready. The app side stops at "first-run profile, then Tonight".
- In the app, NOT built: sign-in (Apple, email link and code), the Keep the book sheet, every consent ask except the microphone, notifications, language choice, goals, invites, universal links, model download. The mobile package has no Supabase, analytics, Sentry or notifications dependency (apps/mobile/package.json:123-170).
- Server side of sign-in IS built and tested: profile-on-signup trigger, `policy_acceptances` and `record_policy_act`, `create_child` and a first-run batch RPC.
- Public claims run ahead of the product. The store listing and website promise backup, family writing, Hindi-English mixing, seven languages, export and Plus pricing. None of these exist in the app today.
- Most serious defects found: (1) a child's name, birthday and signs-as can never be edited after first run; (2) the birthday defaults silently to today; (3) Landing (production default) never shows the App Store badge at launch; (4) one-click unsubscribe from a real mail client gets a 303 instead of 200; (5) Settings Privacy link opens example.com.
