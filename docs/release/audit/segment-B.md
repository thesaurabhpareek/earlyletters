## Constitution check: does any path write or rewrite words outside EditType through verifyEdits?
- Machine path on spoken words: `faithfulClean` (packages/core/src/pipeline.ts:166-208) sends dictionary, filler, repeat, model and rule edits through `verifyEdits` (verify.ts:423). Review calls it with `level:'clean'` and a dictionary only (review.tsx:127). No model or punctuation providers are wired into the app (grep: no `ruleEdits`, `modelEdits` or `acceptSuggestions` in apps/mobile). **Verified. Good.**
- **Violation 1 (CONFLICT, major): `normalizeChars` and `.trim()` run outside EditType and outside verifyEdits**, on typed text and spoken text alike. `cleanedText = normalizeChars(applyEdits(raw, applied)).trim()` (review.tsx:180); also pipeline.ts:201, 225 and segments() at pipeline.ts:251. For a typed letter, `applied` is always `[]` (review.tsx:126), yet `finalText` still differs from what the person typed. Executed in `b-norm.mts`: `She said “hi” — and I’m so proud…  Born 2020–2021.` becomes `She said "hi", and I'm so proud... Born 2020-2021.` The em dash became a comma and no edit is recorded, so it cannot be reversed. iOS smart punctuation produces curly quotes by default, so this hits ordinary typing. Raw is preserved (typed text is stored as `raw_transcript`), so it is recoverable, but not through the verified and reversible path.
- **Violation 2 (CONFLICT, major): "Not much today" writes product-authored sentences into the person's entry.** index.tsx:83-103 stores `rawTranscript = finalText = "{weekday}. Not much today. Just {child}, and us, and an ordinary day."`, `captureMode:'typed'`, signed with the parent's name. COMPONENTS.md:400 specifies the hint "Marks today without writing anything." `templateAlt` (strings.en.ts:190-194) holds mood lines such as "Tired tonight. Loved {child} all day anyway." and is unused today.
- Person's own inline edit (`userText`, review.tsx:431-440) is stored as `finalText` without verification. That is correct under the constitution because it is the person typing, but `machineEdits` is still saved alongside text that no longer equals `applyEdits(raw, applied)` (review.tsx:256-257).
- `raw_transcript` immutability on device: enforced only by SQL shape (`setDraftTranscript ... WHERE raw_transcript IS NULL`, store.ts:661-663; `ON CONFLICT` omits raw, store.ts:398-402; `setWordsForWaitingEntry` guard, store.ts:499-514). The local SQLite has no trigger. The Postgres trigger is server-side (UNVERIFIED by me).
- `withoutEdit` (pipeline.ts:223-226) re-derives text from the remaining edits without re-running `verifyEdits`. In `b-undo.mts` a rule-punctuation put-back gave `um Today Asha laughed...` and `verifyEdits` re-check rejected nothing, so I could not demonstrate a violation. It is latent and not reachable now, since the punctuation provider is not wired. UNVERIFIED, minor.
