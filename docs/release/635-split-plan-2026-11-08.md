## 5. Conflict with #520 in `age-gate.ts`

Verified by `git merge-tree` of #520's head (`ae39522a`, pushed 21:47 UTC) against #635's head: exactly one conflict, in `apps/mobile/src/lib/age-gate.ts`, and it is one line, the import from `./store`:

- #520: `import { deleteSetting, getSetting, setSetting, subscribeTo } from './store';`
- #635: `import { deleteSetting, getSetting, hasAgreement, recordAgreement, setSetting, uuidv7 } from './store';`
- Resolution: the union of both lists. `store.ts`, `strings.en.ts`, `repos/index.ts`, `README.md` and `DEVICE_TEST_PLAN.md` auto-merge.

Meaning checks (read, not run):
- #520's new effect in `useAgeGate` calls `readDecision()` and sets the decision only when it is not `'pass'`. With #635 the decision type is `EntryDecision` (`'agree'` is a new non-pass value). A settings change on a build 1 install (passed, no agreement) will therefore move the decision to `'agree'`, which is the intended screen. `recordAgreement` emits `'settings'` after its transaction commits, so the subscriber reads `'pass'` and does nothing; the screen's own `refresh` completes the move, as before.
- #520 adds a literal `AGE_STOPPED_AT = 'ageGate.stoppedAt'` to `store.ts`; after part 3 the constant exists in `age-gate.logic.ts`. A one-line cleanup follow-up for whoever merges second.
- Erase everything (#520) wipes every table through `sqlite_master`, so `agreements` is covered with no change, and the person sees the full screen again. Both PR bodies say so; not run.

The split helps here: only part 3 touches `age-gate.ts`. Parts 1 and 2 can merge before or after #520 with no conflict. Whichever of part 3 and #520 merges second resolves the import line. Recommendation: let #520 go first or second as the founder prefers (#520 is 2126 added lines over 32 files and needs its own split), and give whoever merges second the exact resolution above.
